# 月次提出PDFの日別打刻明細（2026-11-10、未公開修正版）

## 今回の不具合

社員別/月別の署名付きV3には全勤務区間と休憩開始/終了があり、monthly-report.jsも全日の表を組み立てていた。しかしapp.cssのカード表示向け `.secondary-page .table-scroll { display:none }` がPC/スマホの両幅で適用され、印刷にも継承された。印刷側はoverflowだけを戻していたため、PDFから明細表が丸ごと抜け、氏名・取得日時・合計等しか残らなかった。

## 修正版の責務

admin-timecard-records.htmlだけがmonthly-report.cssを共通CSSの後に読み、検証済みでhidden解除済みの#monthly-report内だけ表を表示する。他の日別カードや権限確認前のhiddenは解除しない。印刷はA4横、列見出しの再掲、行途中の改ページ防止、日付/合計の途中折返し防止。CSV・署名・DTO・GAS・保存処理は変更しない。

日別の出勤/退勤、全休憩の開始/終了、休憩時間、実働時間、状態を残す。同日複数勤務は別行、複数休憩はセル内に全件改行表示、日またぎも実日付を保持。現在ある氏名/社員番号/店舗/対象月/取得時刻/退勤済み区間数/実働合計/休憩合計/未退勤区間数を削除しない。未退勤は未確定、記録なしを休日や0時間にしない。合計は退勤済み区間のみ。承認済み訂正反映後の提出値であり、変更前の原打刻一覧と呼ばない。

## 検査と再現

`node --test tests/monthly-report.test.mjs` と全UI検査329件に成功。ブラウザ印刷は `node qa/verify-monthly-report-print.mjs`。開発用Playwrightが必要で、アプリ本体に追加依存はない。既存環境のモジュールを使う場合はTLH_PLAYWRIGHT_MODULEにplaywrightの場所、TLH_CHROME_EXECUTABLEにChrome実行ファイルを設定できる。

QAは実HTML/CSS/表示controllerに架空社員だけを渡し、外部通信をfile以外すべて遮断する。旧CSSで表が消えることを再現し、新CSSでは390px/1280px/印刷で表示、hidden時は非表示を確認。生成PDFは `.sandbox-work/monthly-report-print/monthly-attendance-details-sample.pdf`。`python qa/check-monthly-report-pdf.py`（pypdfが必要）でPDF本文の1〜30日、複数勤務・複数休憩・日またぎの時刻と既存合計を照合する。2ページに出ることとページ見出し/罫線/折返しを描画画像で確認。実在社員の記録はテストに使用していない。

# 本社提出用・月次勤務記録

最優先は社員別・暦月の退勤記録を本社へ提出できること。管理→「月次記録・提出用出力」→社員と月を選択すると取得する。「月次記録をCSV保存」または「印刷・PDF保存」を押し、保存内容を確認して利用者が本社へ提出する。アプリから自動送信しない。

1日〜月末の各日を含み、勤務は区間別。中抜けを実働へ足さず、夜勤は翌日の退勤日時を記載する。記録なしは休日/勤務なしと断定しない。未退勤・休憩中は未確定、合計は退勤済み区間だけ。停止済み社員の過去記録も管理者は確認できる。

氏名・社員番号・取得日時もGASの同じ署名付き返信から表示する。社員/月変更、再取得、管理権限を確認できないとき、退場後は出力できない。CSV/PDFは取得時点の写しで、再訂正後は更新して出し直す。保存ファイルは利用者が管理し、アプリから後で消せない。

CSVは日本語向けUTF-8 BOM/CRLF、セル内引用符/改行と数式開始文字に対処する。印刷はA4横で提出表だけ。PDFはブラウザの印刷ダイアログから保存する。ミリ秒を保持し、原簿や集計を丸めて変更しない。給与・法定時間外を確定する出力ではない。

魔改造MAP: `monthly-report.js`のbuild/csvが列と区間単位、`app.css`のprintが印刷、`attendance-journal.js`のparseReportがDTO/対象対応。privateのAttendanceJournalService/Bridgeと同期。UIの表示名を社員キーにせず、元記録/role/受付は変えない。削除すると月次出力だけ停止し、保存済み原簿は残る。

検証はmonthly-reportと全UI/実GAS連結。書式変更とデータの意味の変更を区別し、法律上の給与計算をCSV整形へ足さない。
