# ボタンを押さずに情報を表示する

確認ボタンは、自動表示を禁止するGASの制約ではありません。試験時に「読む」と「保存する」を区別していた設計を、通常利用へ調整します。GAS/Sheetsの読取は必要なので待ち時間は残りますが、押す操作を省けます。

| いつ | 自動取得するもの |
|---|---|
| LINE準備後の打刻画面 | 勤務状態、本日の予定と記録 |
| 記録タブの初回表示 | 本日・今月の完了勤務集計 |
| 管理タブの初回表示（管理者確認済み） | 管理者登録画面の読取確認、労務設定の要対応一覧 |
| アカウント情報ページを開く | 自分の登録情報 |
| 本人の日別記録ページを開く | 今月の記録 |
| 日別記録で月/対象社員を変更 | 選んだ対象の記録。社員は勝手に選ばない |
| 管理者の訂正/承認ページを開く | 名簿取得後に承認待ち一覧 |
| 打刻の保存成功 | 勤務状態、本日の記録を更新。集計は次に表示するとき再取得 |
| 直接訂正/承認の反映成功 | 承認待ち一覧を再取得 |

管理者権限・社員一覧・承認待ち件数の起動時取得は従来どおりです。全画面を一斉に取得せず、`auto-read.js`のキューが表示対象の読取を順に実行します。定期ポーリング/自動再試行/新しいタイマー/外部ライブラリはありません。既にその読取が通信中なら結果を使い、同じ取得を重複送信しません。1画面の初回取得は滞在中1回、再取得は更新ボタンです。タブを往復するたびの全取得はしません。他の人の変更も常時配信ではないため、必要時に更新します。

自動実行の許可表は`reads`です。登録・打刻保存・申請・承認・停止・再送・訂正previewを追加しないでください。社員選択や時刻確認、保存前の同意は省略しません。タイムアウト/不明結果は既存controllerが表示し、勝手に保存や再送を行いません。

魔改造MAP: `auto-read.js`は直列化/初回重複抑止、`layout.js`のonActivateは表示通知だけ、各bootstrapはLINE/管理者確認後の取得開始、`punch.js`のonRecordedは検証済み保存成功の通知です。削除すると自動取得だけ止まり、既存更新ボタン/保存原簿は残ります。`aria-busy`はcontrollerが決め、キューはMutationObserverで完了だけ観察します。見た目で成功を判断しません。個人情報のStorageキャッシュは作らず、退場で待機キュー/監視を捨てます。

検証: `node --test tests/*.mjs`。auto-read/layout/punchで連打、直列化、権限拒否、画面離脱、既存timeout、保存確定後だけの再読取を検査し、private側の固定ソース連結試験も更新します。GAS/API/保存先は変更しません。

## 戻る・進むで復元されたとき

ブラウザのbfcacheは画面とJSを丸ごと保存して復元します。古い管理者確認や、退場で止めたcontrollerを使い回さないよう、`pageshow`の`persisted=true`だけを検出してページを一度読み直します。通常の起動・タブ切替では読み直しません。新しい画面でLINE本人確認と表示対象の読取をやり直し、登録・打刻・訂正・承認・利用停止を自動再送しません。この処理を削除すると履歴から戻った画面が停止したままになる場合があります。

登録と従業員情報の訂正/停止も、`pagehide`で待機タイマー・確認内容・招待コード・入力した氏名を破棄し、遅延応答や署名検証中の応答で復活させません。コピー中の結果表示も退場後は更新しません。サーバー側の処理を取り消す機能ではありません。通信中に離れた場合は既に保存済みの可能性があるため、戻って登録状態/対象の情報を確認してから次の操作をしてください。
