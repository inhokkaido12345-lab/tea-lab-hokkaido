# ボタンを押さずに表示する読取

## 取得するタイミング

| 画面 | 初回の取得 | 更新 |
|---|---|---|
| 起動/打刻 | 管理権限・打刻準備・本日記録を1 POST | 打刻成功後に必要な本人記録を更新。手動更新も可 |
| 管理ホーム | 起動群の後、権限がある場合に名簿と承認件数 | 承認等の保存確定後に古い件数を破棄して再読取 |
| 記録 | 日次/月次をまとめて取得 | 更新ボタン、確定した保存後の無効化 |
| その他 | 本人アカウント情報を同じタブ内へ初回表示 | アカウント情報を更新。戻るだけでは重複しない |
| 従業員シフト | 本人monthReadで月全体の両半月 | 月変更、シフトを更新、必要な保存後の無効化 |
| 管理シフト | 管理者batchReadを1回 | 管理月変更、再読み込み、管理側の保存確定後 |

従業員シフトと管理シフトの月・入力・結果不明状態は独立します。本人monthRead→管理者monthRead→シートbatchReadという旧3連続起動ではありません。管理者READを一般従業員へ送りません。

## 自動で行わないこと

取込み・シート作成・締切設定・打刻保存・招待・申請・承認・停止・訂正preview・再送は本人の明示操作です。正本シートの常時監視や他人の変更のPush配信もありません。取得した表示を最新の保存認可に使い回しません。

管理保存で本人の未送信希望を消さないよう、入力中/通信中/結果不明/プレビュー中の自動再取得を見送り、更新案内を出します。手動で未送信入力を破棄するときだけ確認します。保存成功と未確認結果を区別します。

## コードと削除影響

auto-read.jsは固定READの順番・初回重複防止・無効化・完了監視、home-read.jsは起動/記録の一括返信、layout.jsは画面の表示通知、schedule-workspace.jsは本人/管理の接続を担当します。controllerの署名/型検査・最新GAS認可は別です。キューを消すと自動表示が止まり、原簿が消えるわけではありません。

pagehideで待機・秘密・入力を破棄し、遅い返信で再表示しません。bfcacheのpageshow.persistedは一度再読込して最新本人確認へ戻します。通信中に退場してもサーバー処理の取消しにはならないため、保存状態を確認してから次の操作へ進みます。

`node --test tests/*.mjs`と固定UIの連結検査で、権限拒否・重複防止・入力保護・退場・遅延返信・保存自動再送がないことを確認します。
