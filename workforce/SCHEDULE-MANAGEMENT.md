# シフトの管理：シート編集・月全体公開と希望休

2026-11-10の未公開候補。従来の半月公開とは異なり、公開前にGAS→画面の順で配布が必要です。[現在地](CURRENT-STATUS.md)。

## シフト編集・公開

1. 管理する月を選ぶ。
2. 新しい月は「該当月の入力シートを作成」。既存の入力は上書きせず、新規月の従業員メモだけ直近過去月から引き継ぐ。
3. 「入力シートを開く」から勤務・公開/非公開備考・用事・休暇・共有イベントを編集する。[入力形式](SHEET-INPUT.md)。
4. 「下書きを公開する」で正本を読み、差分件数と内容を確認して実行。必要な月全体の取込み後、月全体を一度に公開する。希望の締切前でも公開できる。

半月の選択は不要。1〜15日だけ記入すれば、その記入内容を含む月全体を公開し、残りの日は未設定として表示する。空欄を公休や0時間に変換しない。既存勤務/備考の空欄は削除として反映するので、確認画面を必ず読む。

既に公開した勤務の変更は本人同意・管理者承認待ちにする。月全体公開にしたことを、同意なしの書換えに利用しない。原打刻と履歴は保持。管理者本人の希望は従業員側から提出する。

## 希望休

「希望休」内で、希望の開始日・終了日・締切日時（日本時間）の3項目を設定する。例：2027-01-01〜2027-01-15の希望を2026-12-20 18:00に締め切る。月またぎ・年またぎも可。シフトの作成・公開期間には適用しない。

設定のない日は申請可。設定後は締切ちょうどから通常希望を閉じる。重なる日には後の設定を優先し、期間外の日と提出済み申請は保持する。旧半月の締切は読取互換として表示し、新設定と重なる日だけ上書きする。年休等の申出と確定後の変更申請は別の既存契約。

承認待ちは選んだ月全体を日付順に表示。氏名（社員番号）、対象日、内容、理由を確認し、判断理由を付けて承認/見送る。全日希望休承認は、その月の入力シートの非公開備考へ追記。先に該当月の入力シートを用意する。予定との競合では既存勤務を残し「【希望休と競合】」を追記して編集を案内する。申請しただけで勤務や入力シートを自動作成しない。

## 月別メモ・保存の境界

YYYY-MM従業員メモは初回作成時だけ直近過去月から社員IDで継承。その後は各月独立。既存月は上書きせず、旧共通表や過去月を勝手に削除しない。管理者用参考メモで、全員向けの帳票へ流さない。

結果不明は同じ操作で確認する。シート確認後に正本digest・期待版が変わったら停止。月全体の公開版は両保存区分を一体で追記し、失敗時に片方だけ公開しない。期間締切の変更も固定ID・版・保存読戻しを使う。

## 保守・再構築

表示はadmin-schedule.html、通信/確認/再送はschedule-management.js、DTO検査はschedule-management-contract.jsとschedule.js。GASはScheduleBatchServiceのmonthPublish/deadlineRange、既存ScheduleStoreの補償・追記・追加締切表を使う。Sheet入力正本と別の編集入口を作らない。

初回の期間締切設定だけ既存シフト台帳内にScheduleDeadlinesを作成。READでは作らず、既存表・原打刻は変更しない。削除/改造時はbackendの列辞典・API.md・両repoのテストと同期する。GAS編集画面の手入力は使わない。

```powershell
python scripts/sync-schedule-workspace.py
python scripts/build-workforce-design-preview.py
python scripts/sync-worktime-url.py
python scripts/sync-worktime-url.py --check
node --test tests/*.mjs
```

隣接backendのtestsと固定UI版のintegrationも実行する。候補を検査し公開承認後にGAS→画面の順で配布。既存の社員・打刻・実シフト・権限・通常打刻受付を変更するための承認とは区別する。
