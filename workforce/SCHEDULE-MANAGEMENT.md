# シフト管理：シート編集・公開と希望休

2026-11-10の月単位表示の変更候補です。公開前は従来の対象期間選択が残ります。未設定月の希望受付を実装したため、公開はGAS→画面の順が必要です。公開中のGASはv78のままです。公開状態は[現在地](CURRENT-STATUS.md)を確認してください。

管理→シフトの管理は「シフト編集・公開」「希望休」の2分類だけです。従業員のシフトタブは全員の確定予定と本人の申請・同意専用のままです。

## シフト編集・公開

1. 管理する月を選びます。入力シート・申請一覧は月全体です。翌年の月も選べます。
2. 新しい月は「該当月の入力シートを作成」。確認後に作成します。作成済みの勤務・備考・メモは上書きしません。
3. 「入力シートを開く」から、勤務・備考・用事・休暇・イベントを編集します。社員番号・氏名・日付・行構造は壊さず、[入力形式](SHEET-INPUT.md)に従います。
4. 「下書き公開」内の「公開・変更反映する日付」で1〜15日／16日〜月末を選びます。「下書きを公開する」を押すと、初めて正本シートの差分を読みます。変更件数を確認して実行すると、月全体の変更を反映し、選択した半月だけを公開します。別の取込みボタン・CSV選択・画面内のセル編集・下書き一覧はありません。

**勤務・備考の空欄は削除として反映します。** 公開には希望受付と締切の設定が必要で、希望締切前は公開できません。シート入力はその前からできます。未設定の日を公休や0時間とみなしません。

公開済み期間ではボタンが「シートの変更を反映する」に変わります。変更理由を確認し、勤務の変更は本人同意・管理者承認を経ます。公開済み勤務を直接書き換える入口にはしません。

## 希望休

「希望休承認」では選んだ月全体の承認待ちを日付順に確認します。公開する日付の選択は申請一覧に影響しません。「希望受付の設定」には1〜15日と16日〜月末の締切を別々に表示し、設定ボタンに対象日付を明記します。締切未設定でも希望は申請可。翌年の月も選択できます。締切設定後は、その締切前だけ通常希望を受けます。設定前の古い画面は版競合で読み直しを求めます。年休等の申出と確定後変更は別区分です。全日希望休を承認して非公開備考へ記入するには、その月の入力シートを先に作成してください。申請しただけでシートや確定勤務を自動作成しません。申請には氏名・社員番号・日付・勤務区間・理由を表示します。判断理由と確認後に承認／見送りを記録します。年休等の申出・確定後の変更案もここで扱い、通常希望の締切と制度上の申出は区別します。

全日の希望休承認は正本シートの非公開備考へ「希望休」を追記します。既存予定と競合する場合は「【希望休と競合】」を併記し、既存予定を残してシートでの調整を案内します。承認だけで勤務を削除・確定公開しません。他の申請は従来どおり、正本との一致・本人同意・最新の版を確認します。

## 月ごとの従業員メモ

シート作成時に `YYYY-MM従業員メモ` も用意します。「当月メモ（管理者用）」だけを編集します。初回作成時に直近の過去月から社員IDでコピーし、過去月がなければ空欄です。コピー後は各月独立で、前月の後日の修正も、作成済み翌月への修正も自動伝播しません。社員番号の変更で別人のメモを継承しないよう、非表示の社員IDを変更しないでください。

旧共通の「従業員メモ」は通常の入力先ではありません。現在店舗では空の旧表だけ2026-11-10に削除済みです。他環境の記入済み旧表は自動削除・推測移行しません。メモを勤務制約として自動判定せず、従業員全員の閲覧・帳票・給与計算には渡しません。

## 失敗・再送と保守

シートの確認後にシートやアプリ側の版が変わったら止めます。取込み後、公開直前にも確認時のシートdigestを照合します。保存結果が不明なら、画面の「同じ操作で結果を再確認」を使い、別の保存を重ねません。新規送信と同じIDによる結果照合を混同しないでください。

表示は `admin-schedule.html`、状態・署名通信は `schedule-management.js`、応答の型検査は `schedule-management-contract.js`。ホームへは `scripts/sync-schedule-workspace.py` で合成します。旧 `admin-schedule-bulk.html` は新入口へ案内するだけです。旧CSV・セル編集の資産は互換検査のため残っていますが、現役のホーム・管理ページから読み込みません。

backendでは `ScheduleInputSheet.gs` が月別メモの初回継承、`ScheduleSheetAuthority.gs` が正本差分と取込み、`ScheduleService.gs` が受付・承認・公開時digest照合、Storeが保存読戻し・補償を担当します。見た目の分類を権限判定に使わず、GASが毎回認可します。

```powershell
python scripts/sync-schedule-workspace.py
python scripts/build-workforce-design-preview.py
python scripts/sync-worktime-url.py
python scripts/sync-worktime-url.py --check
node --test tests/*.mjs
# 隣接するbackendのルートで
node --test tests/*.mjs
node --test integration/*.test.mjs
```

新APIを先にGitHub main→既存GASへ公開し、その後に画面を公開します。既存の設定・権限・実打刻・シフトの移行や、実際の入力タブ作成は配布とは別です。GASのソース手編集は行いません。
