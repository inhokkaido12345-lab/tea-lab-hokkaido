# シフトを自分で直す・拡張するための地図

シフトタブはカレンダー/本人申請を直接表示。前半1〜15日・後半16日〜月末で締切/公開/版を独立管理します。ホームはLIFFを再初期化せず、既存auto-readのscheduleキーで読取だけを初回開始。受付状態はフォーム外へ説明し、確定後は変更案/本人同意/承認で編集できます。詳しくは[SCHEDULE.md](SCHEDULE.md)。

最初に[使い方](SCHEDULE.md)を読み、見た目の変更は[デザインガイド](DESIGN.md)へ。ここは「どこを直すと何に影響するか」の案内です。GitHub mainが唯一の正本です。GAS編集画面へコードを貼らず、private repoの自動配布を使います。

## 誰が見て、誰が操作するか

| 内容 | 一般従業員 | 有効な管理者 |
|---|---|---|
| シフトタブ・全員の確定シフト・公開特記事項 | 閲覧・共有用出力 | 閲覧・共有用出力 |
| 自分の希望・申出・変更申請・同意 | 本人分だけ | 従業員でもある場合は本人ページで本人分だけ |
| 管理タブ内の「シフトの管理」入口 | 表示しない | 起動時の署名付き権限確認後に表示 |
| 全員の下書き・申請理由・予定の編集・判断・確定公開 | 不可 | 管理者ページで可能 |
| 非公開メモ・個別の用事の名称/場所 | 本人分だけ | 管理者ページで確認 |

「管理者」は特定の氏名・社員番号・端末ではなく、共通TLHアカウントに現在有効な `TLH_ADMIN / GLOBAL` がある人です。将来別の人へ同じ権限を付ければその人も利用できます。一般の従業員登録ではこの管理者権限を付けません。

入口の非表示は誤操作防止です。公開サイト上の管理用HTMLの存在を隠す認可方式ではありません。URLを直接開く、ブラウザでhiddenを外す、送信するaudienceをadminに変えるといった操作でも、GASが公式LINE本人確認・現在のアカウント・固定の権限を再確認します。

起動時確認は1回です。起動後の権限取消しを常時監視しないため、開いたままのボタンが直ちに消えるとは限りません。保存/管理読取りは毎回サーバーで拒否し、確認できなかった状態を許可に変えません。退場時は管理入口を閉じます。

## 入力から表示・保存への流れ

```text
HTML（ラベル・入力欄）
 → schedule.js（入力を固定・送信・返信の署名と型を検査）
 → GAS Bridge（公式LINE tokenを確認）
 → Service（現在の権限・対象社員・期限・版・同意）
 → Model（時刻・複数勤務・用事の算入を計算）
 → Store（専用Sheetへ履歴を追記・公開版を照合）
 → 共有用/本人用/管理者用のDTOを分ける
 → schedule.jsで文字列として表示
 → schedule-report.jsへ共有用だけ渡し、印刷/PDF・CSVへ
```

DTOは「画面へ返すために必要な項目だけを集めたデータ」です。保存用のplanやSheetの行全体を返さないことが、非公開情報を守る境界になります。HMACは今回の要求と返信の対応・改ざんを検査する仕組みで、管理者権限を付与する仕組みではありません。

## ファイルの担当と削除した場合

| ファイル | 担当 | 削除した場合 |
|---|---|---|
| index.html / layout.js | 5タブ・管理入口の表示とキー移動 | ナビが停止。保存先のデータは消えない |
| admin-access.js | 起動時1回の管理権限確認と署名検査 | 管理入口は初期の非表示/無効のまま |
| schedule.html / admin-schedule.html | 本人用/管理者用のラベル・入力・専用iframe | 対応する画面が開けない |
| schedule-view.js | 日別索引とJST/翌日表示。DOM・通信なし | カレンダー/印刷の計算が停止 |
| schedule.js | 入力・通信・版・再送・画面への描画 | シフト画面の操作が停止 |
| schedule-report.js | 全員向け確定情報の表・PDF印刷・CSV | 出力が停止。元の予定/打刻は残る |
| schedule.css | カレンダー・入力区間・印刷専用の配置 | 表示や印刷に崩れ。認可は変更されない |
| GAS ShiftScheduleModel | 予定時間・重複・休暇・用事の検査 | 予定の検査/保存が停止 |
| GAS ScheduleService / Store / BridgeSchedule | 業務条件/保存/本人確認と返信 | シフトの読取り・保存が停止。原打刻は別 |

共通アカウントはprivate repoの `gas/account`、勤怠とシフトは `gas/workforce` にあります。シフト表は共通Accountを複製せず既存の社員IDを参照します。保存先のタイトルは目印であり、接続先はIDとpurpose/列で検証します。

## よくある魔改造と変更する場所

| 変更したいこと | 入口と一緒に確認する場所 |
|---|---|
| 色・字体・余白・アイコン | app.css・schedule.css・index.html。hidden/disabledの解除で見た目を直さない |
| 日別カード/作成フォームの順序 | 両HTMLとschedule.js。既存id・iframe名・labelの対応を保つ |
| 新しい入力欄 | HTML、fill（読込と消去）、inputPlan（送信）、validPlan（応答）、GAS Model/Store/Service |
| 全員へ出す項目 | Serviceの共有DTO、UIのvalidate/描画、出力の許可列、他社員へ秘密が出ない検査 |
| PDF/CSVの列 | reportのheaders/build、両HTMLのthead、print CSS。管理画面のDOMをそのまま印刷しない |
| 希望の締切や公開条件 | Service/ModelとUIの案内・無効化条件。年休等の別区分を通常希望の締切で拒まない |
| 新しい役割 | サーバーの固定role/scopeを先に設計。画面のaudienceや表示名だけで権限を増やさない |
| 新しい保存項目 | 既存JSON/hashとの互換性を確認。過去版を手編集して合わせず移行と検査を設計 |

一般化の考え方は「見た目」「業務判断」「計算」「保存」「出力」を分けることです。例えば印刷レイアウトの変更で予定時間を再計算せず、計算ルールの変更で認可を迂回しない構造を守ります。

## 保存と公開で壊しやすい点

- 月が未設定でも下書きは作れます。最初の保存でDRAFT月と予定を一緒に記録します。希望受付を後で開始しても下書きは残ります。公開は希望締切後です。
- 保存は履歴の追記です。確定公開は全件のコピー・件数/hash照合が揃ってから切り替えます。途中まで保存した予定を一部だけ全員へ公開しません。
- `note` は非公開、`publicNote` は明示した共有欄です。既存noteを公開欄へ転記しません。空のpublicNoteを省略するのは、旧版の正規JSON/hashを保つためです。
- 「応答がない」は未保存とは限りません。結果不明なら同じ内容・同じ操作IDで再確認します。入力を変えながら同じIDを使わず、更新ボタンと保存の再確認を区別します。
- 表示する更新日は公開版のサーバー時刻です。下書きや非公開申請の保存日を全員向けの更新日にしません。配布ファイルは取得時点の版であり、自動更新されません。

## 手を入れた後の確認

1. 対象のテストを実行し、認可・公開範囲・保存を変える場合は両repoの全テストと連結も確認します。PowerShellでnodeが見つからない場合は、このPCのCodex同梱Nodeを使います。
2. ローカルの通常検査は `node --test tests/*.mjs`。private repoの連結は `node --test integration/*.test.mjs`。連結の公開画面参照はcommit/hash固定なので、変更後はmanifestとworkflowを同じ公開commitへ合わせます。
3. GASソースを変える場合はprivate repoで組立・verifyを行い、GitHub mainから既存Actionsで配布します。先にGAS、次に画面を反映して双方を照合します。Modelを変えた時は計算見本の生成も同期します。
4. 架空データの検査と実端末での確認は分けます。実社員の打刻・権限・希望・確定シフトを検査のために変更しません。PDFは本人の端末で保存後の改ページ・文字切れも確認してください。

新シフトと旧ShiftPlanの日別予定比較の接続、給与計算、有給残数は別工程です。予定差を法定残業と呼ばず、シフトPDFを実際の出退勤原簿として提出しないでください。

## コードを読みやすく、繰り返し処理を減らす整理

schedule.jsのrenderは概要と各描画の呼出し、renderCalendarは予定、renderRequestsは申請、sharedPlanTextは共有欄を担当します。schedule-view.jsのgroupByDayで一度だけ日別に振り分け、カレンダーと印刷で全件を日数分検索し直しません。workTextは時刻の表記だけを共通化し、予定実働の再計算や非公開情報の共有はしません。新しいscriptは両HTMLでreport/controllerより先に読み込みます。

索引は取得済み返信から作る一時的なMapです。別の月へ移動/再読取したら新しく作り、StorageやGASのグローバル変数へ保存しません。layoutのgroupPanelsも起動中のDOM参照だけです。入力や保存の内容をキャッシュする仕組みではありません。

GASの返信用DTOは同じ保存行の正規化を一つの返信中だけ再利用します。架空の30日分で60回から30回へ減りましたが、実際の待ち時間が半分になるという意味ではありません。GAS起動・LINE確認・Sheetの読取りなどの通信待ちは別です。古い権限を使い回したり履歴検査を削って高速化しないでください。

印刷用の表データとDOM（画面要素）は別です。通常表示では全行の印刷DOMを作らず、印刷ボタン/beforeprintで一度だけ組み立て、afterprintで消します。CSVは同じ共有用データから直接作ります。新しい出力方法を足す際も、再読取/失権/退場後に旧データを出力しない境界を維持してください。
