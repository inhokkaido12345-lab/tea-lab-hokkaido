# 社員選択・承認待ち通知・見出しの改造

管理者確認後、そのページで1回だけ既存GASへ読取を送り、従業員一覧と承認待ち件数を取得します。定期監視やスマホへのプッシュ通知ではありません。更新ボタン/ページ再読込で新しい状態を確認します。通知は管理タブ・管理見出し・「訂正と承認」に「● 件数」で表示します。0件は非表示、未取得/失敗も非表示ですが状態欄に未確認と表示します。承認後は古い件数を破棄し、一覧を自動再取得します。

既存の従業員を指定する3欄（日別記録、直接訂正/承認、氏名訂正/利用停止）は`社員番号（氏名）`の選択式です。招待待ち/停止済みには状態も添えます。停止済みを選べても、操作ごとのサーバー検査を通らなければ変更できません。新規社員番号を作る登録欄は入力式です。対象の氏名・入社日の照合、プレビュー、確認同意は省略しません。

`option.value`には社員番号だけ、`textContent`には見せる文字を置きます。DBの`employee_code`と`name`は別々で、連結値を書き込みません。氏名や一覧を公開HTML/JS、URL、Storageへ保存しません。退場/権限喪失で候補と通知を消します。ページ内に保持した候補が古い場合も、保存側は毎回最新の対象と権限を確認します。

改造MAP:

- `admin-overview.js`: 署名/DTO検査、名簿・通知の状態。削除すると候補と通知が取得不能。
- private GAS `AdminOverviewService.gs` / `BridgeAdminOverview.gs`: 最新の固定管理権限で読取。名簿は最大1000人、超過/重複/未知状態は部分取得せず要確認。承認件数は既存の正式申請群の検証を共有し、保存行数を数えません。
- `pending-approvals.js`: 一覧取得後の件数更新、選択から既存プレビューへの接続。選択だけでは承認しません。
- `app.css`: `h1`は画面目的、`h2`/`.group-label`は話題、`.eyebrow`/`.subtle`は補足。管理の大見出しも`.page-heading`に置き、白カードへ入れません。`.group-label`は16px/700/本文色に統一。通知は`.approval-badge`。`hidden`/`disabled`をCSSで解除しないでください。

検証は`node --test tests/*.mjs`、private側の同名テストとintegration、GAS配布の全ソース照合、GitHub Pages公開の照合です。実LINEでは管理タブの通知→一覧→対象氏名→内容確認を確認します。試験のために本物の打刻や申請を増やさないでください。
