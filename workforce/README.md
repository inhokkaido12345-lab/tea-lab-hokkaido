## 訂正申請・承認待ち・中抜け（2026-11-03）

従業員用の「自分の打刻の訂正を申請する」を打刻/勤務記録に設置。管理者用の直接訂正・承認は従来どおり権限確認後のみ選択できます。管理タブを開けない従業員もSELF申請を利用します。
管理者は訂正ページ上部の「承認待ちを確認する」で、氏名（社員番号）・対象日付きの一覧を読みます。各カードの「内容を確認する」は既存のREVIEWプレビューへ進むだけで、まだ承認しません。全勤務/理由を確認して実行した後は古い一覧を消し、再読取します。1ページ50件、続きも確認できます。
中抜けは「退勤→勤務状態の確認→再出勤」です。1日の中で繰り返し通常打刻でき、区間の間は実働にも休憩にも含めません。各勤務内の休憩は開始/終了を押します。日別カードは勤務1/勤務2…と休憩時刻を分けて表示します。未退勤の区間は未確定です。
訂正/申請では「＋ 中抜け後の勤務を追加する」で最大10区間、各区間に休憩1回またはなしを入力できます。その日全体を置換するので、残す勤務もすべて入力します。通常打刻は1勤務内で複数の休憩も記録可能ですが、この訂正フォームの休憩は各区間1回までです。
新UIは専用V2 actionを使います。旧GASでは未知actionとして保存せず、新GASは旧action/旧監査も維持するため、配布順の違いで複数区間が1勤務へ潰れて保存されない設計です。

**見た目を自分で調整する場合は[デザインの考え方・魔改造ガイド](DESIGN.md)へ。** 配置の理由、一般化できる概念、色/余白/文字/タブの変更箇所、共有範囲、具体例、確認手順をまとめています。app.cssも番号付きの説明と読める改行で整理しています。

3. 出勤日はJST。出退勤日時、任意の休憩開始/終了、理由を入力し内容を確認します。最大10勤務区間・区間ごとの休憩0/1組で、日全体を置換します。複数勤務/複数休憩のある日は置換範囲に注意します。
4. 確認した対象と時刻に同意して実行します。本人申請は申請番号を管理者に渡し、管理者が社員番号/申請番号で確認して承認します。
5. 別の日や別モードの操作はページを再読込してから行います。入力変更で前のプレビューは無効になります。

原PunchLogは変更せず、既存CorrectionRequests/Corrections/AdminAuditLogに履歴を保存します。承認後は勤務状態・日別・日次・月次・次の通常打刻が同じ投影を使います。
日時欄は分・秒・小数秒を受け付けます。不備があれば該当欄に案内しフォーカスします。休憩は両方空欄か、出勤と退勤の間の正しい順序で入力してください。
予定超過はmax(0,実働−予定実働)。法定時間外や給与計算とは別です。予定なし/未終了を0に変えません。予定編集の専用UI、申請の却下/取消は未実装です。承認待ち一覧は管理者だけが利用できます。

## 通信と改造の約束

GitHub mainが正本です。GASはprivate repo `tlh-platform` からActions/claspで配布し、GASのコードを手で編集しません。新しい外部サービスを追加しません。
画面のタブは認可ではありません。本人と権限はGASが毎回検査します。返答は通信枠/子孫の送信元、origin、nonce、action、型、HMACを確認した場合だけ表示します。
token/個人時刻/氏名/社員番号/招待秘密/鍵をURL・console・localStorage・sessionStorageに保存しません。確認済み入力とgroup/revisionを保持し、画面を離れると消去します。
「応答を確認できません」は自動再送しません。同じ申請番号の状態読取へ戻り、不明なまま新規操作を重ねません。

文言・順番はHTMLと対象controllerから変更します。DOM id/init/iframeの参照を先に検索してください。DTO/action/署名変更はprivate repoのBridge/Service・両repoの試験・説明を同時に更新します。
private repoの連結試験は公開画面のcommit/hashを固定します。JS/HTMLを変えた場合は固定manifest2つとworkflowも整合させ、作業中checkoutを勝手に巻き戻しません。
