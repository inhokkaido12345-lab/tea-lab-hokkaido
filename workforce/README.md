# TLH Work Time：利用・開発・改造の入口

勤怠・シフト管理のオンラインWebアプリです。制作元は **TEA LABORATRY HOKKAIDO**。表示名だけを変更しており、URLと内部識別子の `/workforce/` は維持します。

[現在地](CURRENT-STATUS.md) → [従業員ヘルプ](employee-help.html)／[管理者ガイド](admin-guide.html) → [シフト運用](SCHEDULE.md) → [説明書索引](DOCUMENTS.md) の順に読んでください。過去の改修メモは[整理前の記録](history/20261109-README.md)へ分離しました。

## 1. 現在使う機能

| 利用者 | 操作 | 入口 |
|---|---|---|
| 従業員 | 出勤・休憩開始/終了・退勤。同日再出勤にも対応 | 打刻タブ |
| 従業員 | 日別/月次記録、本人の打刻訂正申請 | 記録タブ・本人用訂正画面 |
| 従業員 | 全員の確定シフト閲覧、本人の希望休・変更申請 | シフトタブ |
| 従業員 | 社員番号・本人のTLHアカウント情報、ヘルプ | その他タブ（情報を自動取得） |
| 店舗管理者 | 従業員の事前登録/招待/訂正/停止、社員番号変更 | 管理→従業員の管理 |
| 店舗管理者 | 日別/月次出勤簿、直接訂正、申請の承認 | 管理→出退勤の管理 |
| 店舗管理者 | 正本シート取込み、希望確認、半月別締切/確定公開、PDF/CSV出力 | 管理→シフトの管理 |

管理者本人の訂正申請も従業員側から行います。管理タブは管理作業専用です。管理タブの表示/非表示は認可ではなく、GASが毎回本人・会社・店舗・権限を検査します。

LINEログインが初版の認証方法です。独自ID/パスワード・メール/SMS認証は未導入。PWAもオンライン必須で、オフライン打刻はできません。運営管理Webはコード配布済みですが、専用台帳・初期運営権は未設定です。給与・法定割増の完全計算や新環境での完全復元は完成していません。

## 2. シフトはシートで編集、アプリで取り込む

1. 管理→シフトの管理→「シフトの入力・取込み」へ進み、対象月を読み込みます。
2. 「入力シートを開く」で勤務・公開備考・非公開備考を入力します。用事・休暇詳細・共有イベントは同じファイルの月別補助タブへ入力します。
3. 「入力シートから直接取り込む」で変更前後を確認し、「確認した正本シートを取り込む」を押します。
4. 希望受付/確定公開は別の半月管理画面で行います。1〜15日／16日〜月末の締切と公開は独立です。

**正本シートの勤務・備考の空欄は削除として反映します。** `【空にする】` の入力は不要です。日付・社員番号・行構造を削除せず、既存月を作り直さないでください。アプリからの勤務・備考編集とCSV入力は現行店舗では表示しません。希望休・変更申請・打刻はアプリに残します。詳しくは[SHEET-INPUT.md](SHEET-INPUT.md)。

## 3. 新しいPCで開発と検査を始める

GitとNode.js 22を用意します。Googleログインやnpm installなしで画面試験を実行できます。

```powershell
git clone https://github.com/inhokkaido12345-lab/tea-lab-hokkaido.git tea-lab-hokkaido-work
Set-Location tea-lab-hokkaido-work
git status --short
node --version
node --test tests/*.mjs
```

既存フォルダがあるときはcloneや上書きの前にGitの状態を確認します。実LINEログインはHTTPS上の既存設定が必要なので、ローカル検査は架空DOM/LINE/通信と実WebCryptoを使います。HTMLを直接開いただけで実打刻を試さないでください。[試験の説明](../tests/README.md)。

GAS側を変更する場合は隣にprivate `tlh-platform-work` を取得し、そちらのREADMEに従います。連結試験は13個のUI参照とworkflowで固定した版を使います。hash不一致を無条件に書き換えず、実装差分を確認します。

## 4. ファイルの責務・削除影響・魔改造MAP

| 変えたいこと | 主なファイル | 責務と注意 |
|---|---|---|
| 色・余白・字体・タブ配置 | app.css / layout.js / index.html | CSSの変数・番号付き節から変更。hidden/disabledをCSSで解除しない。字体は同梱IBM Plex Sans JP |
| 打刻 | punch.js / home-read.js | 保存確認・同じ操作IDの再送・重複防止を外さない。時計shell.jsは表示だけ |
| 記録・出勤簿 | attendance-journal.js / monthly-report.js | 本人と管理者の入口を分離。印刷/CSVに非公開情報を混ぜない |
| 本人申請・直接訂正・承認 | day-change.js / day-change.html / admin-day-change.html | SELF/DIRECT/REVIEWの契約を維持。原PunchLogを書き換えず履歴で訂正 |
| シフト読取・希望・承認・公開 | schedule.js / schedule-view.js / schedule-report.js | 従業員の申請と管理者の正本編集を区別。予定未設定を公休・0時間にしない |
| 正本シート取込み | schedule-bulk.js / schedule-bulk-model.js | controllerが署名と状態、Modelが変換を担当。Sheetモードでは隠れた編集表を作らない |
| 旧環境のCSV互換 | schedule-sheet.js | 未設定環境のため保持。現行店舗へ旧手順を案内しない。削除前にHTML/試験/呼出元を検索 |
| LINEログインとアカウント | account-info.js / auto-read.js / current-workplace.js | 本人情報はその他で自動取得。店舗表示は認可の代用にしない |
| 遠隔復旧・運営・試験 | recovery.html / operations.js / sandbox/ | 通常勤怠と別の受付/権限/保存先。実装済みを有効化済みと誤解しない |

ファイルを消す前に`rg`でscript読込・init・DOM id・iframe・試験を検索します。コード冒頭には責務、呼出元/先、削除影響、一般概念、改造箇所、秘密の境界、検証方法を残します。変更したJSのURL版も更新し、古いブラウザキャッシュの混在を防ぎます。

## 5. 公開・障害時の約束

ソースの唯一の正本はGitHub mainです。UIは既存Pages、GASはprivate repoから既存Actions/claspで配布します。GAS編集画面や生成物を手で直しません。新しい外部サービスは増やしません。**シフト入力データの正本がシートであることと、コードの正本がGitHubであることは別です。**

1. 変更差分・既存の未コミット変更を確認し、対象試験と連結試験を実行します。
2. PRの検査を確認してmainへ反映します。GAS契約も変える場合はGAS→画面の順です。実データ/権限/受付設定の変更はコード公開と分けます。
3. 公開ファイルとcommitの一致、読取り表示を確認します。確認用の架空打刻を実原簿へ作りません。
4. 応答不明時は同じ操作の状態を確認し、新規送信を重ねません。コードを戻す場合はGitHubのrevertと同じ配布経路を使います。コードを戻しても実データや設定は戻りません。

token・招待秘密・鍵・個人時刻・氏名をURL/console/localStorage/sessionStorageへ残しません。APIの型/action/nonce/HMAC/認可を説明整理のために変えません。完全復元・新規初期管理者は未実証なので、コードと説明書だけでデータも復元できるとは扱いません。
