## 従業員シフトと管理シフトを分離（2026-11-09）

従業員用「シフト」＝全員の確定閲覧・本人の希望申請・本人同意。管理→「シフトの管理」＝入力シート・取込み・希望確認・承認・締切・公開。管理者本人でも両者を混ぜません。各画面を開いた時だけ、その役割の固定READを自動実行します。月選択と未保存/結果不明/プレビューの状態は独立させ、他方の操作で入力を変更しません。保存・認可・希望休の非公開備考追記は従来どおりです。

## 希望休の承認と非公開備考（2026-11-09）

全日の「希望休」を管理者が承認すると、入力シートの該当社員・日の【非公開備考】へ「希望休」を改行で追記します。既存メモは残し、同じ行は重複させません。勤務・用事・別の休暇等と競合する場合は「【希望休と競合】」も追記し、画面に入力シートでの編集を案内します。**希望休の承認だけで勤務欄・確定シフトは変更しません。** 管理者がシートを調整し、既存の取込み・確認・公開の手順へ進みます。

提出・閲覧・却下では追記しません。年休・時間休・勤務変更・管理者変更案は従来の正本一致と本人同意を維持します。承認と追記は読戻しまで一体として確認し、途中失敗は今回分だけ補償。同じ操作IDの再確認は追記しません。手入力が変わっていたら上書きせず、補償もできなければ要点検として停止します。Googleの共同編集を完全に排他する仕組みではないため、承認中は対象セルの編集や行列の並替え・構造変更を避けてください。

## 労務設定の専用ページ（2026-11-09）

管理見出し付近の「労務設定の要対応事項を確認」から`labor-policy.html`へ進みます。ホームの各管理カテゴリへ一覧は展開しません。専用ページでLINEと管理者権限を確認後、既存の署名付きREADを自動実行します。未確認・取得失敗を解消扱いにせず、閲覧だけでは警告を消しません。ホームでは労務READを送らず、打刻や保存設定は変えません。従来の「管理の一番下」の配置説明は過去の仕様です。

管理→「従業員の管理」の登録フォームは、権限確認後に自動表示します。フォームを開くボタンは不要です。既存の自動READを使い、登録・招待発行は明示操作だけで実行します。

記録タブは「今日の勤務」→「今月の勤務」→「日別の退勤記録を見る」の順です。日別画面では出退勤・休憩を確認でき、本人の訂正申請への入口も残しています。集計・保存処理は同じです。

## シフトの役割別作業場・月暦（2026-11-09）

従業員用の「シフト」タブには、1日〜月末のカレンダーと本人の希望・変更申請だけを表示します。管理者本人が開いても管理操作は混ぜません。管理者のシート取込み・希望確認・承認・締切・公開は、「管理」→「シフトの管理」の一画面にまとめます。旧単独URLは互換入口として保持し、管理用ページからは管理側へ戻ります。

カレンダーは月全体、締切・申請・承認・公開・共有出力は従来どおり半月別です。希望入力の先頭に対象半月の締切（日本時間・締切済み/未設定）を表示。スマホも7曜日の月暦を保ち、横スクロールで見ます。

monthReadは両半月を1回の署名付きREADで取得。取得済みの半月切替では追加通信しません。管理者データは別フォーム/ID/返信iframeで分離し、最新サーバー認可を維持。自動取得は既存キューでREADだけを順に実行し、取込み/承認/公開を自動実行しません。プレビュー/応答不明中は対応する役割側の月選択だけを停止します。従業員と管理の月は独立し、管理内だけ取込みと希望確認の対象月を同期します。

## 月をまたぐ従業員メモ（2026-11-09）

入力ファイルの「従業員メモ」は全月共通の管理者用参考情報です。「継続メモ（管理者用）」列へ「火木不可」などを記入します。勤務の入力/取込みの禁止条件にはせず、月別の非公開備考や公開シフト/PDF/CSVへ自動転記しません。メモの編集はシートで行い、アプリは手編集しません。

内部employee_idで紐付け、社員番号変更時もメモを保持。新規月作成の明示操作では表を用意し、不足する社員行と社員番号/氏名の参照だけ更新します。既存メモ・過去社員の行は消しません。単なる読取り・取込みでは表を作成/更新しません。内部ID/ヘッダーを編集せず、メモ列だけを記入します。

## 2. シフトはシートで編集、アプリで取り込む

1. 管理→「シフトの管理」→「シートを開く・取り込む」へ進み、対象月を読み込みます。
2. 「入力シートを開く」で勤務・公開備考・非公開備考を入力します。用事・休暇詳細・共有イベントは同じファイルの月別補助タブへ入力します。
3. 「入力シートから直接取り込む」で変更前後を確認し、「確認した正本シートを取り込む」を押します。
4. 希望受付/確定公開は別の半月管理画面で行います。1〜15日／16日〜月末の締切と公開は独立です。

**正本シートの勤務・備考の空欄は削除として反映します。** `【空にする】` の入力は不要です。日付・社員番号・行構造を削除せず、既存月を作り直さないでください。アプリからの勤務・備考編集とCSV入力は現行店舗では表示しません。希望休・変更申請・打刻はアプリに残します。詳しくは[SHEET-INPUT.md](SHEET-INPUT.md)。

## 3. 新しいPCで開発と検査を始める

GitとNode.js 22を用意します。統合画面のHTMLを再生成する場合はPython 3も使います（標準ライブラリだけで、追加パッケージ不要）。Googleログインやnpm installなしで画面試験を実行できます。

```powershell
git clone https://github.com/inhokkaido12345-lab/tea-lab-hokkaido.git tea-lab-hokkaido-work
Set-Location tea-lab-hokkaido-work
git status --short
node --version
node --test tests/*.mjs
```

既存フォルダがあるときはcloneや上書きの前にGitの状態を確認します。実LINEログインはHTTPS上の既存設定が必要なので、ローカル検査は架空DOM/LINE/通信と実WebCryptoを使います。HTMLを直接開いただけで実打刻を試さないでください。[試験の説明](../tests/README.md)。

GAS側を変更する場合は隣にprivate `tlh-platform-work` を取得し、そちらのREADMEに従います。連結試験は13個のUI参照とworkflowで固定した版を使います。hash不一致を無条件に書き換えず、実装差分を確認します。

## 5. 公開・障害時の約束

ソースの唯一の正本はGitHub mainです。UIは既存Pages、GASはprivate repoから既存Actions/claspで配布します。GAS編集画面や生成物を手で直しません。新しい外部サービスは増やしません。**シフト入力データの正本がシートであることと、コードの正本がGitHubであることは別です。**

1. 変更差分・既存の未コミット変更を確認し、対象試験と連結試験を実行します。
2. PRの検査を確認してmainへ反映します。GAS契約も変える場合はGAS→画面の順です。実データ/権限/受付設定の変更はコード公開と分けます。
3. 公開ファイルとcommitの一致、読取り表示を確認します。確認用の架空打刻を実原簿へ作りません。
4. 応答不明時は同じ操作の状態を確認し、新規送信を重ねません。コードを戻す場合はGitHubのrevertと同じ配布経路を使います。コードを戻しても実データや設定は戻りません。

token・招待秘密・鍵・個人時刻・氏名をURL/console/localStorage/sessionStorageへ残しません。APIの型/action/nonce/HMAC/認可を説明整理のために変えません。完全復元・新規初期管理者は未実証なので、コードと説明書だけでデータも復元できるとは扱いません。
