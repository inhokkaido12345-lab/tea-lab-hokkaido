# TLH勤怠管理：画面の説明と改造入口

## 現在地（2026-11-03）

### UI2：打刻・記録・管理・その他

所有者がレイアウト見本を確認し、実画面への反映を了承。`app.css`で色/余白/レスポンシブ配置を統一し、`layout.js`は4画面のwrapperだけを切り替えます。`shell.js`の時計は表示用で、打刻の保存時刻には使いません。
ホームは「勤務状態を確認する」→状態に合う打刻ボタンの順です。「記録を確認」は既存の署名付き日別APIで本日の予定・打刻を読みます。打刻後に本日欄を更新する場合はこの読取ボタンを押します。初期通信・自動打刻・新しい権限付与は追加しません。
記録タブに今日/今月の完了分と日別ページへの入口、管理タブに社員番号指定の記録・直接訂正/申請承認・登録/属性訂正/停止、その他へ招待受取と診断を配置しました。
日別ページは署名/DTOを通った値だけでカードを作り、対象変更・再読取・退場で古いカードを消します。未退勤は未確定、予定なしの超過は未設定として区別します。
見本の架空氏名・時刻・予定は実画面へコピーしていません。実データの読取前には未確認を表示します。`day-change.html`の見た目も合わせていますが、プレビュー/同意/保存/不明結果の制御は元のままです。

| 新しい部品 | 削除影響・改造先 |
|---|---|
| app.css | ホーム/日別/訂正の見た目が崩れる。色はCSS変数、幅はmedia query。hidden/disabledを上書きしない |
| shell.js | 表示時計のみ停止。保存や認可には関与しない。退場で更新intervalを解除 |
| AttendanceJournal.renderCards | 本日/日別カードの表示停止。認証/署名/DTO検査は既存controllerで先に行う |

キーボードは左右/Home/Endで4タブを移動できます。ソースの固定参照はprivate repoのmanifest2つとworkflowへ同期します。旧5ファイルに加えCSS/時計/日別controller/日別HTMLも連結側でhash検査します。

LINEログインで使う簡易な勤怠画面です。出退勤/休憩・日別一覧・管理者直接訂正・本人申請/承認を公開済み。架空社員で4打刻と訂正両経路の保存を確認しました。実社員開始とは別で、打刻受付は最後の確認でOFFです。
一般登録・遠隔LINE復旧も閉鎖中。独自パスワード・メール/SMS認証はまだありません。デザインの磨込みは後回しです。

## ファイルの責務・消した場合

| ファイル | 担当・削除時の影響 |
|---|---|
| index.html / layout.js | 従業員/管理者タブと操作の入口。layoutは表示だけ、権限や送信中の状態を変えない |
| punch.js | 勤務状態の確認と本人の4種打刻。消すと打刻できないが原簿は残る |
| daily-summary.js / monthly-work-summary.js | 今日/今月の完了分。時間表示helperは共有なので参照検索してから変更 |
| timecard-records.html / attendance-journal.js | 本人または管理者の指定月の日別表。削除すると一覧停止、保存済みデータは残る |
| day-change.html / day-change.js | SELF申請、DIRECT直接訂正、REVIEW承認。削除すると訂正入力停止。GAS側の投影は残す |
| recovery.html / account-recovery.js / recovery.css | 遠隔LINE復旧の専用画面。公開済みだが受付OFF、通常打刻から分離 |
| sandbox/ | 分離した試験Account登録/照合。通常勤怠の保存先や権限を流用しない |
| tests（repoルート） | 架空DOM/通信による画面検査。実LINEやGoogle Sheetsは変更しない |

## 日別の確認と訂正

1. 日別記録を開き、LINEで準備後、月と「表示する人」を選びます。管理者として他の社員を見る場合は社員番号を指定します。
2. 日別表のリンクから訂正画面へ進みます。自分の申請・管理者の直接訂正・管理者の承認を明示的に選びます。管理者が自分の申請を作る必要はありません。
3. 出勤日はJST。出退勤日時、任意の休憩開始/終了、理由を入力し内容を確認します。初版は1日1勤務・休憩0/1区間の日全体の置換です。複数勤務/複数休憩のある日は置換範囲に注意します。
4. 確認した対象と時刻に同意して実行します。本人申請は申請番号を管理者に渡し、管理者が社員番号/申請番号で確認して承認します。
5. 別の日や別モードの操作はページを再読込してから行います。入力変更で前のプレビューは無効になります。

原PunchLogは変更せず、既存CorrectionRequests/Corrections/AdminAuditLogに履歴を保存します。承認後は勤務状態・日別・日次・月次・次の通常打刻が同じ投影を使います。
日時欄は分・秒・小数秒を受け付けます。不備があれば該当欄に案内しフォーカスします。休憩は両方空欄か、出勤と退勤の間の正しい順序で入力してください。
予定超過はmax(0,実働−予定実働)。法定時間外や給与計算とは別です。予定なし/未終了を0に変えません。予定編集の専用UI、申請一覧/却下/取消は未実装です。

## 通信と改造の約束

GitHub mainが正本です。GASはprivate repo `tlh-platform` からActions/claspで配布し、GASのコードを手で編集しません。新しい外部サービスを追加しません。
画面のタブは認可ではありません。本人と権限はGASが毎回検査します。返答は通信枠/子孫の送信元、origin、nonce、action、型、HMACを確認した場合だけ表示します。
token/個人時刻/氏名/社員番号/招待秘密/鍵をURL・console・localStorage・sessionStorageに保存しません。確認済み入力とgroup/revisionを保持し、画面を離れると消去します。
「応答を確認できません」は自動再送しません。同じ申請番号の状態読取へ戻り、不明なまま新規操作を重ねません。

文言・順番はHTMLと対象controllerから変更します。DOM id/init/iframeの参照を先に検索してください。DTO/action/署名変更はprivate repoのBridge/Service・両repoの試験・説明を同時に更新します。
private repoの連結試験は公開画面のcommit/hashを固定します。JS/HTMLを変えた場合は固定manifest2つとworkflowも整合させ、作業中checkoutを勝手に巻き戻しません。
