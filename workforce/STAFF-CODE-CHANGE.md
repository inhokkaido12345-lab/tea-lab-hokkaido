# 社員番号を変更する

管理タブ→従業員の管理→「打刻履歴を保持して社員番号を変更する」を開きます。ログインした管理者だけが保存できます。画面を直接開けることは管理権限があることを意味しません。

1. 現在の社員番号・氏名・入社日（未指定なら空欄）と、変更後の番号を入力します。
2. 「変更内容を確認する」を押します。この段階では保存しません。
3. 表示内容を確かめ、「確認した社員番号へ変更する」を押します。
4. 勤怠画面へ戻り、最新名簿を更新して確認します。

内部の従業員ID、LINE連携、打刻・訂正・シフト・既存招待は保持します。別の従業員の使用中番号へは変更できません。番号を移す場合は先に元の人の番号を変更します。

結果不明時は入力を変えず同じ保存ボタンで確認してください。閉じた場合は名簿の新旧番号を読み直します。Sheetの直接編集や従業員の削除・再登録は不要です。変更前に開いていた打刻画面は状態を更新してから本人が操作します。

## 自分で改造する入口

- `staff-code-change.html`：入力と明示確認。削除でこの画面だけ停止。
- `staff-code-change.js`：通信、署名確認、結果不明時の同じ操作の保持。保存や権限の本体はGASです。
- `tests/staff-code-change.test.mjs`：連打、偽応答、通信結果喪失、画面離脱を架空データで検査。
- backendの`StaffCodeChangeService.gs` / `BridgeStaffCodeChange.gs`：固定認可・内部ID維持・番号重複・監査・再送の本体。

一般化の鍵は「履歴の内部IDと表示番号の分離」です。魔改造で番号を履歴の結合キーへ戻さないでください。氏名・token・名簿をURLやStorage・公開ソースへ保存しません。会社別の番号変更権限は別途実装するまで閉じています。

Node.js 22で`node --test tests/*.mjs`。画面・API双方を変更したらbackendの連結試験も実行します。コード配布はGitHub mainが正本です。
