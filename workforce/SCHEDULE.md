# シフト・希望の提出と管理

独立した「シフト」タブが入口です。従業員:「シフト・希望の提出」。管理者: 同じタブの「シフト作成・希望の確認」（起動時の権限確認後に表示）。初版の認証は既存LINE、同じTLHアカウント/従業員情報を使います。従業員へGoogle Sheetsを共有する必要はありません。

## 初めて月のシフトを作る

1. 管理者は月・従業員・日付を選び、勤務区間や休みを下書き保存します。希望0件・締切未設定でも作成可能です。最初の保存で「下書き作成中」の月ができます。下書きは従業員へ公開されません。
2. 希望を受け付けるときに「希望受付の設定」で締切を日本時間で設定します。既に作った下書きは残ります。通常の希望は受付開始後に提出します。
3. 従業員は日付・希望区分・休暇や勤務・特記事項・理由を提出します。管理者は希望を承認して下書きへ反映、または理由を付けて見送りを記録できます。本人は未処理の自分の申請を取り消せます。
4. 「月全体の下書き・確定予定を見る」を開いて確認します。勤務区間は複数入力でき、中抜け・翌日退勤を明示します。空白を休日や0時間とみなしません。
5. 希望締切後に「下書きを全員へ確定公開」。確定した勤務・一般化した休暇・共有イベント・公開特記事項を全員へ共有します。希望が必ず届いている必要はありません。公開前の受付/締切設定は必要です。

## 特記事項の公開範囲

「全員に公開する特記事項」は、例えば「地元に帰省（北海道に居ません）」のような共有用です。確定シフトの本人の行へ全員向けに表示します。従業員も希望・変更申請へ入力でき、管理者の承認と確定公開を経て反映します。公開後に内容を変える場合も、既存の申請・同意・承認の経路を使います。

「非公開の特記事項」は本人・管理者だけです。希望理由、用事の名称/場所、休暇の詳しい事情も従来どおり全員には出しません。既存のメモを公開欄へ自動転記しません。公開欄は初期値空欄なので、共有したい内容を明示して記入してください。

月暦は月末と曜日を計算。祝日名や営業上のイベントは管理者が手入力します。自動で祝日や祭りを選ぶ機能ではありません。イベントは日ごと1つの名称/補足欄へまとめて入力し、確定後も更新できます。

## 確定後の変更

従業員からは初回締切に関係なく変更申請できます。管理者が承認するまでは確定シフトを変えません。管理者が既存予定を編集した場合は、直接上書きせず本人への変更案になります。本人がその内容へ同意→管理者が最終承認の順で反映します。同意なしの案を承認するボタンは出しません。

他の更新で対象版が変わっていた場合は再確認します。本人同意を別の変更案へ使い回しません。申請/同意/判断と公開履歴は削除せず版で残します。

## 休暇・勤務算入・実績との境界

通常の希望締切と、年休等の制度上の申出を分けます。初版の休暇入力は全日。有給を選んだ申出は通常希望の締切で拒否せず年休の区分で扱い、管理者が内容を確認します。有給残数の引去り、時間単位休暇の運用、給与・法定時間外の計算が完成したという意味ではありません。

会社が指示・拘束する用事は勤務対象から外せません。算入外の分類が未確認の用事は下書き保存できますが、予定実働を確定して全員公開することはできません。予定休憩を会議の重なりで自動的に減らしません。

シフトは予定、打刻は実績です。新シフトは専用カレンダーで閲覧します。旧「日別勤務とシフト」の予定差は従来のShiftPlanによるもので、新しい複数区間予定へ自動移行した表示ではありません。月次の本社提出は実績のみで、シフト未設定でも出力できます。

## 保存・失敗時・自分で改造する

GitHub main→既存GAS→既存シフト専用Sheetの順。共通Account/原打刻を複製せず、専用表のemployee_idが既存従業員へ対応します。保存先名は「TLH｜シフト・希望休・変更申請」。ファイル名は目印、接続はprivate設定のIDとpurpose/ヘッダーで検証します。

保存は追記した版と内容hash、操作者、日時、操作IDを持ちます。全員向け公開は全件の複製とhashの一致を確認します。途中保存を一部だけ公開しません。保存失敗は追加した行だけを補償し、補償を確認できなければシフト専用の要確認フラグで停止します。打刻の原簿や共通アカウントの停止フラグとは分けています。

結果不明は自動再送しません。「同じ操作で保存結果を再確認」は同じ内容/操作IDで確認します。最新状態の更新と、別内容での新しい保存を混同しないでください。画面を離れると秘密と申請入力を消し、履歴から戻った画面は新しい本人確認から再開します。

改造MAP: schedule.html/admin-schedule.htmlは入口・ラベル、schedule.cssは月暦/区間の配置、schedule.jsは入力/署名検査/描画。GAS側のScheduleServiceが最新権限/締切/同意、ScheduleStoreが列と履歴/公開の整合性、既存ShiftScheduleModelが日時/複数区間を計算します。UIのdisabledや管理タブを認可の代わりにしないでください。削除時はホーム入口とscript/iframe/相手Bridge/テストも検索します。

## 更新日の確認・LINE/メールでの共有・印刷

確定シフトの最終更新日時を日本時間で表示します。公開版が保存したサーバー時刻を使い、下書きや非公開の申請を保存しただけでは日時を変えません。画面に表示するのは取得した時点の公開版です。配布前には「最新の状態に更新」で読み直してください。

1. シフト画面（本人・管理者のどちらでも可）で対象月の確定版を取得します。
2. 「印刷・PDF保存」を押し、印刷画面でPDF保存またはプリンターを選びます。A4横、日付/曜日・社員番号/氏名・勤務区間・予定休憩/実働・休暇・公開特記・共有イベントの一覧です。複数区間と翌日退勤も残します。人数が多いと複数ページになります。
3. 保存したPDFを確認してLINE/メールへ添付します。アプリが自動で送信する機能ではありません。「CSV保存」でも同じ共有情報を保存できます。LINE内で保存/印刷できないときは通常のブラウザでログインし直して開きます。

出力は全員向けの確定DTOだけから別表を組み立てます。管理者の下書き・希望理由・非公開メモ・本人だけの用事詳細は出しません。空の日は「予定未設定」であり、休みや0時間とは扱いません。確定前・読取り中・失権・画面離脱では出力を無効にして表を消します。勤務予定の出力なので、本社提出用の実際の出退勤原簿とは区別してください。

改造入口はschedule-report.js（共有列の許可リスト/CSV/印刷操作）、両HTMLのschedule-report表とthead、schedule.cssのprint節です。列は3か所とテストを同期し、管理者の画面全体やprivate planを印刷対象にしないでください。CSVは数式開始文字を無害化し、Blob URLを読取り直し/離脱で解放します。追加通信や外部PDFサービスは使いません。
