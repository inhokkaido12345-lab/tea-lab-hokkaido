# 打刻画面の本人確認と再ログイン

2026-11-05、本人の承認後にPR #11をmainへ反映して公開しました。既存の受付ON・勤怠原簿・認可は変更しません。[現在の公開状態](CURRENT-STATUS.md)。

## 利用者の操作

勤務状態の読取りで本人確認が拒否された場合、またはLINEの本人確認情報が取得できない場合、打刻ボタンを隠して「LINEでログインし直す」を表示します。通信の遅延、受付停止、従業員登録なしを期限切れと決めつけません。

本人がボタンを押すと、外部ブラウザ/PWAは既存LINE SDKでログアウト→ログインし、同じ打刻ページへ戻ります。LINE内は既存ミニアプリの入口を開き直します。勝手にログインへ移動したり、失敗した打刻を自動再送したりしません。戻ったページは通常の読取り・最新認可から開始します。

出勤ボタンを押しても、最初の送信前に本人確認情報が取得できなかった場合は保存処理が始まっていないため、そのまま再ログインできます。送信を試みた後の結果不明とは分けて判定します。

**打刻を送った後に保存結果が未確認の場合は、その固定イベントIDを保持します。** 後の再送で本人確認が拒否されても「保存されていない」とは断定できません。先の送信だけ保存済みの場合もあるためです。この間はログイン遷移を出さず、同じ打刻の再送か、管理者への記録確認を案内します。既存の証明を更新できず再送も通らない場合は、管理者に実記録を確認してもらう必要があります。画面を閉じても秘密情報や未確定操作をブラウザへ保存する仕組みは追加していません。

## 保守・魔改造の入口

| 場所 | 役割・変更時の注意 |
|---|---|
| punch.js / requireLogin | 証明欠落と署名付きLINE_VERIFY_REJECTEDだけを扱う。単なるtimeoutや未検証postMessageで作動させない |
| punch.js / controls | pending・draft・loginRequired・loginPending・stoppedから表示を決める。draft中の遷移禁止を外さない |
| index.html / punch-login | 初期hidden/disabledの本人操作ボタン。既存のパレットとボタンを使用 |
| punch.js / pagehide | タイマーを解除し、遅延応答と操作を停止。履歴復帰は既存auto-read.jsのGET再起動に従う |
| attendance-journal.js / clock | 固定JSTの書式設定を1回だけ生成。個人情報・権限・集計結果をキャッシュしない |

LINE公式の[SDK仕様](https://developers.line.biz/ja/reference/liff/)で、isLoggedIn/getIDToken/logout/loginの役割と外部ブラウザ・LINE内の違いを確認しました。認証の成否は引き続きGASのLINE公式検証で判断し、tokenの自己解読を認可の代替にしません。
