# TLH Inventory

[在庫アプリ](https://tealabhokkaido.com/software/inventory/)。WorkTimeとは別のPWAです。

TLHアカウントでログインし、上部で店舗を選びます。「店舗を作成・招待コードで参加」から利用者が店舗を作成できます。作成者が管理者となり、7日間・1回限りの招待コードでメンバーを追加します。管理者は招待の取消・メンバー解除ができます。WorkTimeの雇用情報は変更しません。TLHアカウントの事前登録は必要です。

新店舗は空です。「仕入品情報」タブで品名・メーカー・複数の仕入先・商品コード・保管方法・規格資料を登録します。包装は「1ケース＝20袋、1袋＝20束、1束＝10g」のように登録し、自動換算します。例の数字を実商品に流用しないでください。重量はg、液体はmL、ストローなどは本数を基準に管理し、異なる次元は混同しません。在庫操作後の基準単位変更は拒否します。価格・原価・POS連携は含みません。

仕入品情報の保存後に店舗別のGoogleスプレッドシートへ一覧を同期します。正本は検証付き原簿です。シートの直接編集はアプリへ反映されません。同期未確認の場合は「一覧シートへ再同期」を押します。在庫操作を重複登録する必要はありません。スプレッドシートの一般公開やGoogleメールアドレスへの自動共有はしません。

入荷は届いた時だけ在庫を増やします。消費計測は登録した1袋・1ケースの使用開始から使い切りまでです。毎回の計測は不要です。対象から順に使い、継ぎ足しや他包装との混用を避けてください。複数包装を同時使用すると店全体の消費速度を表しません。納期は発注〜受取完了で自動学習します。

店舗IDは権限ではありません。サーバーは毎要求でTLH本人確認を行い、最新の在庫サービス所属を検査します。他店舗の商品・履歴・仕入先は返しません。既存のThe TEA店舗だけは従来の固定Coreで認可された従業員向けの互換入口を残します。

PWAのid・scopeは/software/inventory/。認証窓口は既存の/workforce/inventory/auth/を使います。LIFF往復後も同一originのnonce固有BroadcastChannelで結果を受け取ります。token・鍵・結果のブラウザー保存やオフライン送信はありません。

再構築の正本は非公開tlh-inventoryのweb、src、gas、scriptsです。新しいバックエンドAPIを先に配備し、公開healthと匿名拒否を確認してからPWAを更新します。GAS原簿は最大10000操作で停止するため、大規模運用前には保存先の分割・DB移行が必要です。

計測単位は、平日と土日の両方を含み、使い切るまで約1週間かかる1袋・1ケースなどを推奨します。曜日による繁閑の偏りを抑える目安で、7日固定ではありません。大袋などは途中で打ち切らず、実際に使い切るまで測定します。

※土日の方が多く消費する品目を平日だけで計測すると、普段の1週間より消費速度を低く見積もり、在庫切れ予測や発注の判断が遅れるおそれがあります。反対に、土日だけでは速く見積もる場合があります。平日と土日の両方を含めて測定してください。

## 現行品・使用終了と変更履歴

仕入品情報で品目の状態を選べます。使用終了の品目は通常の倉庫一覧・入荷・消費計測・アラートに出しません。在庫数量・注文・規格は削除せず、仕入品情報の「使用終了のみ」「すべて」で確認・再開できます。現行に戻して再開するときは棚卸で残量を確認してください。

製造元・仕入先それぞれに「あの商品と同じ」の参照を設定できます。元の変更も連動します。自身への参照や循環、未登録・別店舗の商品参照は拒否します。参照元の品目を使用終了にしても、参照先の商品まで使用終了にはしません。

仕入先や製造元・規格・状態の変更前後を履歴として固定して保存します。参照元の更新による連動も記録します。「履歴」タブの「仕入品情報の変更前後」と、保存先シートの「変更履歴」で確認できます。これにより過去の仕入先情報を現行の情報で上書きしません。

## カテゴリで品目を探す

仕入品情報で商品を選び、「カテゴリ」の共通25択から選択して保存します。「シロップ・ソース」「果実・果実加工品」「糖類・甘味料」「包材・容器・消耗品」など、食品・飲料から包材まで用意しています。1品目1カテゴリです。冷凍・常温は別の保管方法欄へ記入します。未分類でも保存でき、後から未分類だけを絞り込んで設定できます。

在庫・発注と仕入品情報の一覧でカテゴリと品名・店内通称・商品コードを組み合わせて検索できます。「ピーチ」で店内通称からも探せます。全角・半角の表記差は正規化します。状態条件（要発注、発注済み、現行、使用終了）とも併用できます。カテゴリ件数は検索前の対象品目数です。在庫概況とアラートの判定は全現行品が対象です。

絞り込み・検索のたびに通信はせず、入力中の発注数量・棚卸数量を保持します。店舗切替ではカテゴリと検索をリセットします。旧分類は削除しません。既知の旧名は表示時に共通名へ対応付け、未知の旧名も編集候補に残します。選び直して保存するまで原簿のカテゴリを一括変更しません。分類変更は既存の保存APIと変更履歴・店舗別一覧シートを使い、在庫数量や規格を変えません。

正本web/app.jsのproductCategoriesとcategoryAliases、docs/stores-and-catalog.mdに全分類・改造手順があります。PWAだけを独自に変更するとGAS所有者版とずれるため、正本の画面生成と一緒に更新してください。
