# TLH Inventory

[在庫アプリ](https://tealabhokkaido.com/software/inventory/)。WorkTimeと別のオンラインPWAです。

## 利用を始める

1. 「LINEでログインして在庫を開く」を押します。TLHアカウントは事前登録が必要です。認証情報はページ内だけで、再読込後は再ログインします。
2. 店舗を選びます。新店舗を作る人は「店舗を作成・招待コードで参加」から作成し、他の人は管理者の招待コードで参加します。コードは7日間・1回限り。作成者が管理者です。
3. 仕入品情報で商品・共通カテゴリ・メーカー・仕入先・規格を登録し、在庫を数えるか、届いた数量を入荷で登録します。新店舗は空です。

## 日常の操作

- 在庫・発注：予測とレッドラインを確認。発注数量・予定日は任意で、発注しただけでは在庫は増えません。重ね発注を別々に記録できます。
- 消費を測る：必要な時だけ1袋・1ケースの開始と全量の使い切り。次の計測は自動開始せず、途中残量のg入力はありません。
- 在庫を数える：開封中を含む総量を基準として予測を合わせ直します。
- 入荷：届いた分だけ加算し、対応する注文を受取完了にすると納期を自動学習します。分納は最後の受取まで。安全余裕だけ入力します。
- 仕入品情報：メーカーと最大5件の仕入先、保管方法・資料・単位規格を登録。「他の商品と同じ」で参照し、元の変更を連動できます。
- 履歴：仕入情報の変更前後、参照元の変更による連動を保存。過去の情報を現行値で上書きしません。

## カテゴリと規格

食品・飲料・包材を含む共通25カテゴリから主分類を1つ選んで保存します。在庫と仕入品情報はカテゴリ、品名・店内通称・商品コードで検索できます。「ピーチ」で通称から探せます。未分類・旧分類も保持し、分類変更で数量・規格は変えません。検索・作業切替で追加通信せず、未保存の入力を保持します。

重量はg/kg、容量はmL/L、本数などは個別の基準単位で扱います。「1ケース＝20袋、1袋＝20束、1束＝10g」は説明例です。実商品の内容量を登録し、異なる次元を混ぜません。在庫履歴がある品目の基準単位変更は拒否します。規格変更で過去の入荷量・計測開始時の量を変えません。

使用終了品は通常の倉庫・計測・入荷・アラートから外し、数量と履歴は残します。仕入品情報の「使用終了のみ」「すべて」から編集・再開できます。再開時は棚卸で残量を確認します。参照元を使用終了にしても、それを参照する現行品までは終了しません。

## 計測の目安と限界

平日と土日を含み、使い切りまで約1週間かかる単位が目安です。平日だけでは繁忙日の消費を低く見積もる場合があります。大袋も途中で区切らず、全量まで測ります。継ぎ足し・複数包装の同時使用を避けます。ケースは中身の使用開始から全て使い切るまでです。

平均20標本・直近3標本を使い、在庫は平均速度、発注警告は速い側で推定します。現在は24時間の暦時間ベースで、営業時間・休業日・祝日の自動補正は未実装です。POS・価格・原価・仕入先への注文送信・メールやバックグラウンド通知も未実装です。棚卸で誤差を補正してください。

## エラーの見方

WorkTimeと同じ褐色の「⚠ 要確認」に、確認コードと次の操作を表示します。未ログインの通常案内や保存中をエラーにしません。

| 状況 | 操作 |
| --- | --- |
| 認証失効 | LINEでログインし直す |
| 読込の失敗 | 通信を確認して最新の記録を読む |
| 保存結果不明 | 新しい保存を重ねず同じ操作を再確認 |
| 一覧同期だけ失敗 | 商品を再登録せず一覧シートへ再同期 |
| 原簿・容量の問題 | 記録を削除せず管理者へ確認コードを伝える |

例外全文・token・入力値は確認コードへ出しません。診断表示のための通信・外部ログ・自動再送はありません。起動できない場合も固定のJS確認コードを出します。

## 保存先と再構築

検証付き原簿が正本です。仕入品情報・単位規格・仕入先・変更履歴の別シートは店舗ごとに再生成する一覧です。直接編集はアプリへ反映されません。通常の在庫読取・入荷で一覧を再生成せず、仕入情報の保存・明示再同期だけで更新します。完了済み商品取込の公開保守窓口と配備runnerは廃止しました。過去の取込記録・数量は保持します。

コード正本は非公開tlh-inventoryのsrc・web・gas・scripts、説明はそのルートREADMEです。旧仕様・試作をarchiveへ分離し、現在の操作・Google導入・配布・エラー・性能の説明を集約しました。生成物を手で修正せず、build-employee-pwa.mjsから生成します。資産の内容ハッシュをURLに付け、古いキャッシュの残留を抑えます。PWAのid・scopeは/software/inventory/、認証窓口は/workforce/inventory/auth/です。

サーバーは毎要求で本人と店舗所属を確認し、他店舗の情報を返しません。tokenや操作データを端末へ永続保存しません。原簿は全店舗合計10000操作までで、規模拡大前に分割・DB移行が必要です。模擬テスト、公開ファイル一致、本人の実端末操作は別の確認です。
